# AI-Assisted Development Policy

## Purpose and Scope

This policy applies to contributions created or revised with AI assistance. It supports responsible use of AI throughout development and review.

## Human Accountability

AI assists contributors but cannot assume responsibility for a contribution. Contributors are responsible for understanding their changes and making them available for review. Project maintainers make the final acceptance decision.

## Code Quality

Follow the project's established conventions and keep changes focused on the requested work. Prefer clear, maintainable code and existing validated functionality. Add dependencies only when they are needed.

## Correctness and Testing

Run the checks and tests appropriate to each change. Cover important edge cases and report the commands and results accurately. Do not invent test results, compatibility claims, or standards conformance. Preserve meaningful tests and assertions.

## Security and Privacy

Protect user data, credentials, tokens, keys, and other sensitive information. Validate untrusted input, use safe defaults, and avoid unnecessary permissions. Report identified security risks to maintainers through the appropriate channel.

## Standards and Dependencies

Check relevant standards and technical references when a change depends on them. Evaluate dependencies for suitability and respect their licenses and attribution requirements. Record external sources when they inform the work.

## Documentation

Update documentation when behavior or requirements change. Describe implemented capabilities, partial support, and known limitations accurately. Give readers enough context to verify claims and use the software correctly.

## Git and Pull Request Workflow

Use a separate branch for changes and follow Conventional Commits. Submit changes through a pull request that explains their scope and includes actual test results. Address applicable CI failures and obtain the maintainer's explicit authorization before merging. Repository protections and history changes require appropriate authorization.

## AI Transparency

Describe AI assistance accurately when disclosure is required for a contribution or requested by a maintainer. Do not represent generated material as independently reviewed or invent evidence of human review.

## Review and Acceptance

AI-generated code must receive the same substantive review as other contributions. Contributors should be able to explain the design, results, and limitations. Maintainers decide whether the contribution meets the project's requirements and may be accepted.
